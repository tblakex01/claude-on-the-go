# Code of Conduct

## Our Foundation

claude-on-the-go exists to help people build things and learn the craft of software engineering. We value humility, research, and kindness above all else. Whether you're contributing code, reporting bugs, or answering questions, remember: there's always a better solution than what you came up with, and that's a good thing.

## Core Values

### 1. Respect the Craft
- **Read the documentation.** FastAPI docs, pexpect docs, WebSocket specs - understand what you're using.
- **Understand the architecture.** Check `ARCHITECTURE.md` before proposing changes.
- **Research first.** Show you've investigated at least one source before asking for help.
- **Be humble.** Even when your solution is gold, someone might have platinum. Stay teachable.

### 2. Kindness Over Intellect
- **Being smart doesn't excuse being mean.** Explain clearly, critique ideas not people.
- **Help others learn.** Point to docs, explain concepts, share resources.
- **Patience matters.** Not everyone's at your level yet. They will be if you help them.

### 3. Simplicity Over Complexity
- **Reduce technical debt.** Don't add clever abstractions that make maintenance harder.
- **Necessary dependencies only.** Every new library is a maintenance burden.
- **AI-assisted code is welcome,** but review it critically - does it add complexity? Could it be simpler?

## What We Expect

### When Opening Issues
- **Show your research.** "I read X doc and tried Y, but Z happened."
- **Provide context.** OS, Python version, error logs, steps to reproduce.
- **Be specific.** "WebSocket disconnects" is vague. "WebSocket disconnects after 60s on iOS Safari" helps.

### When Submitting PRs
- **Explain the why.** Don't just say what changed - explain why it's better.
- **Propose improvements.** "This works, but I think we could also consider X because Y."
- **Keep it simple.** If your PR adds 3 dependencies to solve a 10-line problem, rethink it.
- **Test thoroughly.** Run `pytest`, test on actual devices, check edge cases.

### When Reviewing Code
- **Be constructive.** "This could be simpler: [example]" beats "This is too complex."
- **Ask questions.** "Why did you choose this approach?" invites discussion.
- **Acknowledge good work.** If someone nailed it, say so.

## Unacceptable Behavior

- **Harassment of any kind** - racism, sexism, homophobia, transphobia, ableism
- **Personal attacks** - attack ideas, not people
- **Condescension** - "you should already know this" helps nobody
- **Bad faith contributions** - spam PRs, malicious code, intentional complexity
- **Gatekeeping** - telling people they're "not real developers" or similar nonsense
- **Ignoring security concerns** - if someone reports a vulnerability, treat it seriously

## Scope

This applies everywhere the project exists:
- GitHub (issues, PRs, discussions)
- Any community channels we create
- When representing the project publicly

## Reporting Issues

**For conduct violations:**
Open a private issue or contact maintainers directly through GitHub.

**For security vulnerabilities:**
Use GitHub's security advisory system: https://github.com/MatthewJamisonJS/claude-on-the-go/security/advisories/new

We'll respond within 48 hours with confidentiality.

## Enforcement

1. **First violation:** Private warning with explanation
2. **Repeated issues:** Temporary ban from project spaces
3. **Severe violations:** Permanent ban

We aim to be fair, educational, and firm when needed.

## On AI-Assisted Development

AI tools are welcome here. Use them to:
- Generate boilerplate
- Explore approaches
- Speed up implementation

But remember:
- **You're responsible for understanding the code you submit**
- **Simple solutions beat clever ones**
- **AI doesn't replace reading documentation**
- **Review AI output critically** - does it introduce unnecessary complexity or dependencies?

## The Goal

We're here to build things and learn. Help each other get better at the craft. Be humble, be kind, write clean code, and read the docs.

**TL;DR:** Be humble, be kind, do your research, keep it simple. We're all learning.
